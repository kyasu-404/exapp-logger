# Отчёт сдачи

ExApp для Nextcloud, которое фиксирует появление и изменение файлов во всём дереве выбранной папки. Приложение не интерпретирует уровни каталогов и не требует справочников организаций, предметов, классов или типов документов.

Приложение рассчитано на Nextcloud 32–36, AppAPI и HaRP Proxy. Контейнер подключается к HaRP через FRP и Unix-сокет /tmp/exapp.sock.

## Как это работает

Администратор создаёт наблюдение:

- название;
- корневая папка Nextcloud;
- дата начала и окончания;
- статус.

Для любого файла ниже корневой папки сохраняются полный и относительный пути, идентификатор Nextcloud, размер, MIME-тип, etag, время первого обнаружения, nc:upload_time, mtime и состояние. Глубина и названия вложенных папок произвольны.

Webhook Listeners доставляют события:

- создание;
- обновление;
- переименование;
- перемещение;
- копирование;
- удаление.

По умолчанию раз в 45 минут выполняется полная сверка дерева одним рекурсивным запросом WebDAV. Она восстанавливает пропущенные изменения файлов и пустых папок, если ExApp некоторое время не работал. Все пользовательские даты, границы суток и расписания интерпретируются в часовом поясе Europe/Moscow.

## Интерфейс

- **Обзор** — показатели, последние поступления, дерево папок и диагностика webhook/сверки.
- **Наблюдения** — создание и изменение папки, периода и статуса.
- **Файлы** — поиск и фильтры по пути, расширению, дате и состоянию.
- **Активность** — хронология событий со старыми и новыми путями.
- **Отчёты** — XLSX и CSV для всего наблюдения или выбранной ветки, отчёт изменений за период и автоматическое сохранение XLSX в Nextcloud ежедневно, еженедельно или ежемесячно.

XLSX содержит листы «Файлы», «Активность», «По папкам» и «Пояснения». Размер приводится в удобном виде. Количество колонок «Папка N» определяется максимальной глубиной реальных путей.

## Сборка контейнера

~~~bash
docker build -t registry.example.org/nextcloud/file-control:2.3.1 .
docker push registry.example.org/nextcloud/file-control:2.3.1
~~~

Перед регистрацией замените в appinfo/info.xml значения registry, image и image-tag на адрес опубликованного образа.

## Установка

1. Установите и включите AppAPI, HaRP Proxy и Webhook Listeners.
2. Настройте Docker Deploy Daemon с HaRP.
3. Соберите и опубликуйте образ.
4. Зарегистрируйте ExApp:

   ~~~bash
   sudo -u www-data php occ app:enable webhook_listeners
   sudo -u www-data php occ app_api:app:register file_control harp_docker \
     --info-xml=/absolute/path/to/info.xml --wait-finish
   ~~~

5. Создайте группы file_control_admins и file_control_observers либо задайте другие через переменные окружения.
6. Откройте «Отчёт сдачи» в верхнем меню и создайте наблюдение.

После включения ExApp самостоятельно регистрирует интерфейс и необходимые node event listeners.

## Хранилище

По умолчанию база SQLite находится в постоянном каталоге AppAPI:

~~~text
$APP_PERSISTENT_STORAGE/file_control.sqlite3
~~~

Для PostgreSQL задайте DATABASE_URL, например:

~~~text
postgresql://file_control:password@postgres/file_control
~~~

Миграции выполняются автоматически. При переходе с 1.0.x кампании и полезные записи файлов переносятся в новую модель наблюдений; прежние таблицы остаются нетронутым архивом. Содержимое файлов ExApp не копирует и не изменяет.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| DATABASE_URL | SQLite | PostgreSQL или отдельный SQLite URL |
| LOG_LEVEL | INFO | Уровень журналирования |
| DEBUG | false | Подробный локальный режим |
| RECONCILE_INTERVAL_MINUTES | 45 | Интервал сверки активных наблюдений |
| APP_TIMEZONE | Europe/Moscow | Часовой пояс интерфейса, отчётов и расписаний |
| ADMIN_GROUPS | admin,file_control_admins | Группы с правом настройки |
| OBSERVER_GROUPS | file_control_observers | Группы только для просмотра |

## Локальная разработка

Backend требует Python 3.12, интерфейс — Node.js 22 и pnpm 11.

~~~bash
python -m venv .venv
. .venv/bin/activate
pip install -e ".[dev]"
cd frontend
pnpm install --frozen-lockfile
pnpm build
cd ..
pytest
~~~

Тесты проверяют API наблюдений, границы веток, московское время, идемпотентность событий, пустые папки, обновление, перемещение, удаление, миграции, расписания и формирование отчётов.
