# Сбор и контроль файлов

ExApp для Nextcloud, которое ведёт кампании централизованного сбора файлов: определяет организацию и параметры сдачи по пути файла, хранит историю событий, показывает прогресс и формирует отчёты XLSX/CSV.

Приложение рассчитано на Nextcloud 32–36, AppAPI и HaRP Proxy. Контейнер подключается к HaRP через FRP и Unix-сокет `/tmp/exapp.sock`.

## Возможности

- справочник организаций и импорт из CSV/XLSX;
- кампании с отдельной корневой папкой, сроками и набором организаций;
- произвольные уровни классификации: период, тип документа и другие измерения;
- строгая или свободная структура папок;
- требования к сдаче по организации и комбинации измерений;
- обработка создания, записи, переименования, копирования и удаления файлов;
- защита от повторной обработки одного события;
- фоновая и ручная сверка с фактическим содержимым Nextcloud;
- сводка, таблица прогресса, матрица, журнал файлов и журнал событий;
- отчёт XLSX из шести листов и выгрузки CSV;
- роли администратора и наблюдателя по группам Nextcloud.

## Структура пути

Корневая папка кампании задаётся относительно файлов выбранного технического пользователя, например:

```text
/Сбор/2026/Квартальная отчётность
```

Внутри неё первый каталог должен совпадать с полем `folder_name` организации. Следующие каталоги соответствуют измерениям кампании по порядку:

```text
/Сбор/2026/Квартальная отчётность/ООО Ромашка/1 квартал/Баланс/report.xlsx
```

Для строгого измерения значение должно быть заранее добавлено в его справочник. В свободном режиме неизвестное значение сохраняется как текст.

## Сборка контейнера

На машине с Docker выполните из корня проекта:

```bash
docker build -t registry.example.org/nextcloud/file-control:1.0.0 .
docker push registry.example.org/nextcloud/file-control:1.0.0
```

Перед регистрацией замените в `appinfo/info.xml` значения `registry`, `image` и `image-tag` на адрес собранного образа. Реестр должен быть доступен Docker-службе AppAPI.

## Установка в Nextcloud

1. Установите и включите приложения AppAPI и HaRP Proxy.
2. Настройте в AppAPI Docker Deploy Daemon с HaRP как прокси.
3. Соберите и опубликуйте образ, как описано выше.
4. Скопируйте `appinfo/info.xml` на сервер Nextcloud и зарегистрируйте ExApp (имя конфигурации HaRP замените на своё):

   ```bash
   sudo -u www-data php occ app:enable webhook_listeners
   sudo -u www-data php occ app_api:app:register file_control harp_docker \
     --info-xml=/absolute/path/to/info.xml --wait-finish
   ```

   Если HaRP-конфигурация назначена в AppAPI конфигурацией по умолчанию, аргумент `harp_docker` можно не указывать.
5. Включите приложение «Сбор и контроль файлов».
6. Создайте группы `file_control_admins` и `file_control_observers` либо переопределите их через переменные окружения.
7. Откройте приложение из верхнего меню Nextcloud, добавьте организации и создайте первую кампанию.

После включения ExApp само регистрирует необходимые Webhook Listeners. Для активной кампании владелец корневой папки должен совпадать с техническим пользователем, указанным в мастере кампании.

Обычный cron Nextcloud доставляет вебхуки пакетами и может давать задержку до своего интервала. Если события должны появляться почти сразу, запустите постоянные обработчики очереди `OCA\WebhookListeners\BackgroundJobs\WebhookCall` по официальной инструкции Nextcloud; периодическая сверка ExApp всё равно восстановит пропущенные изменения.

## Хранилище

По умолчанию используется SQLite в постоянном каталоге контейнера AppAPI:

```text
$APP_PERSISTENT_STORAGE/file_control.sqlite3
```

Для нагруженной установки задайте `DATABASE_URL`, например:

```text
postgresql://file_control:password@postgres/file_control
```

Версионированные миграции базы выполняются автоматически при каждом запуске; применённые версии отмечаются в таблице `schema_migrations`. Резервное копирование должно включать базу данных; файлы Nextcloud приложение не копирует и не изменяет.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| `DATABASE_URL` | SQLite | PostgreSQL или отдельный SQLite URL |
| `LOG_LEVEL` | `INFO` | Уровень журналирования |
| `DEBUG` | `false` | Подробный локальный режим |
| `RECONCILE_INTERVAL_MINUTES` | `45` | Интервал полной сверки активных кампаний |
| `ADMIN_GROUPS` | `admin,file_control_admins` | Группы с правом изменения данных |
| `OBSERVER_GROUPS` | `file_control_observers` | Группы только для просмотра |
| `MAX_UPLOAD_MB` | `20` | Максимальный размер файла импорта |

## Локальная разработка

Backend требует Python 3.12, интерфейс — Node.js 22 и pnpm 11.

```bash
python -m venv .venv
. .venv/bin/activate
pip install -e ".[dev]"
cd frontend
pnpm install --frozen-lockfile
pnpm build
cd ..
pytest
```

Вне Nextcloud middleware подписи AppAPI отключается, поэтому API можно проверять локально. Это предназначено только для разработки; в контейнере AppAPI запросы проверяются библиотекой `nc_py_api`.

## Ограничения проверки

Локальные тесты проверяют классификацию, идемпотентность событий, расчёт прогресса, импорт и генерацию отчётов. Полная интеграционная проверка требует реального Nextcloud с AppAPI/HaRP, WebDAV и доступным реестром контейнеров.
